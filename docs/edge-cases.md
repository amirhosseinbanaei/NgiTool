# NgiTool edge cases

This is the master list of everything that can go wrong or be unusual in
NgiTool's two subjects, **reverse proxy** and **load balancing**, and on the
system around them. Code, tests and commit messages refer to entries by ID
(`RP-07`, `LB-03`, …). New findings get the next free ID in their group; IDs
are never reused or renumbered.

Status is **done (prompt N)** once the behaviour and its test exist, and
**planned (prompt N)** for the prompt that owns it:

| Prompt | Owns |
|---|---|
| 1 | foundation: UI kit, state, paths, update, install (SYS) |
| 2 | discovery and config parsing (DISC, CONF) |
| 3 | writing config, routes, pools, apply (RP, LB, APPLY) |
| 4 | compose scanning and app lifecycle (DOCK) |
| 5 | the bundled edge stack, certificates, migration from the Node CLI (EDGE, CERT, MIG) |

"Test" says how the entry is proven: a unit test (package and name), a
fixture, or a manual check that is described well enough to repeat. Examples
use `example.com` and made-up project names only.

## DISC — discovery

| ID | Situation | How NgiTool detects it | What NgiTool does | Test | Status |
|---|---|---|---|---|---|
| DISC-01 | No nginx anywhere on the server. | Every probe (processes, systemd units, binaries on PATH, containers, compose files) comes back empty. | Says so plainly and offers the bundled edge stack as the way to start; never guesses an instance. | unit: discover TestNoNginxAnywhere | done (prompt 2) |
| DISC-02 | Distro nginx under systemd, running. | `systemctl show nginx` (ActiveState, MainPID, ExecStart), `/proc/<pid>/cmdline` for `-c`/`-p`. | Lists it as a host instance with its config path, binary, version (`nginx -V`) and reload method (`systemctl reload`). | unit: discover TestHostDiscovery (master in nginx.service, -V, systemctl reload) | done (prompt 2) |
| DISC-03 | nginx installed but stopped or disabled. | Unit exists with ActiveState inactive/failed, or the binary exists with no master process. | Listed as stopped; config is still read from disk; changes are written but not reloaded, with a hint to start it. | unit: discover TestHostDiscovery (inactive openresty.service) | done (prompt 2) — found and read; prompt 3 tests and skips the reload of a stopped instance |
| DISC-04 | Several host master processes (different `-c` or `-p`, e.g. a second nginx on :8080). | One master per `ps` entry whose parent is not another nginx; `-c`/`-p` from cmdline; listening ports from `ss -ltnp`. | Each master is its own instance, named by config path; never merged. | unit: discover TestHostDiscovery (two masters, different -c) | done (prompt 2) |
| DISC-05 | Source-built nginx outside PATH (e.g. `/opt/nginx/sbin/nginx`). | `/proc/<pid>/exe` of the master process. | Uses that binary for `-t`, `-T` and `-V`; shows the path. | unit: discover TestHostDiscovery (/opt/nginx/sbin/nginx via /proc/<pid>/exe) | done (prompt 2) |
| DISC-06 | Variants: openresty, angie, tengine, nginx-unprivileged (listens on 8080, non-root). | `-V` banner (`openresty/`, `Angie/`, `Tengine/`), image name, `User` in the image config, listen ports. | Treated as nginx-compatible with the variant shown; directives the variant lacks are not generated; unprivileged images get 8080-style listens. | unit: discover TestParseVBanners, TestHostDiscovery (angie, non-root master), TestCmdArgsAndExecStart (images) | done (prompt 3) — detected (prompt 2); unprivileged images get 8080/8443 listens and `resolve` follows the variant's core version |
| DISC-07 | Container started with plain `docker run` (no compose labels). | `docker ps` + `docker inspect`: no `com.docker.compose.project` label. | Listed as a container instance; config from its mounts; changes need a reload through `docker exec`. | unit: discover TestDockerDiscovery (static-site, no labels) | done (prompt 2) |
| DISC-08 | A compose project's own nginx, running or stopped. | Compose labels on the container (project, service, config_files, working_dir). | Listed under the project with its service name; stopped ones are still read from the mounted files (CONF-02). | unit: discover TestDockerDiscovery (recorded running projects, exited old-web-1) | done (prompt 2) |
| DISC-09 | An nginx service that exists only in a compose file and was never started. | Compose scan (DOCK-01) finds a service whose image or build is nginx-like and no container exists. | Listed as "defined, not created"; read-only until it has run once, with the command to start it. | unit: discover TestComposeDefinedNeverStarted (resolved and raw-YAML fallback) | done (prompt 2) |
| DISC-10 | An image not named nginx that runs nginx (custom app image). | `docker top` shows an `nginx: master process`, or the entrypoint/cmd runs nginx. | Treated as an nginx instance like DISC-07/08. | unit: discover TestDockerDiscovery (recorded `docker top` of a custom image; stopped image by its cmd) | done (prompt 2) |
| DISC-11 | nginx owned by another manager: nginx-proxy-manager, jwilder/nginx-proxy, swag, Traefik in front. | Image names and labels (`jc21/nginx-proxy-manager`, `nginxproxy/nginx-proxy`, `linuxserver/swag`), docker-gen sidecars. | Listed as read-only with the manager's name: NgiTool never writes where another tool regenerates files. | unit: discover TestDockerDiscovery (nginx-proxy-manager), TestCmdArgsAndExecStart (image list) | done (prompt 2) |
| DISC-12 | Container in host network mode. | `HostConfig.NetworkMode == host`. | Ports are the host's; upstreams follow host rules (RP-05 does not apply); port ownership checked with `ss`. | unit: discover TestDockerDiscovery (hostnet owns :8081 through its worker pid), TestReachFromContainerAndHost | done (prompt 2) |
| DISC-13 | Docker missing, daemon down, rootless docker, podman, or no socket permission. | `docker` not on PATH; `docker info` exit code and stderr (permission denied, cannot connect); `DOCKER_HOST` pointing at a user socket; `docker version` reporting Podman. | Host instances still work; container discovery is skipped with the reason and the fix (doctor shows the same). Podman is reported, not driven. | unit: discover TestDockerStatus (podman, down, denied, slow, rootless ×2, ok); doctor Docker access | done (prompt 2) |
| DISC-14 | Not running as root. | `os.Geteuid() != 0`. | Partial results with the reason on each line that could not be read (other users' processes, `/etc/nginx` not readable); writes refused with the sudo command. | unit: discover TestNotRootReportsFailedReads | done (prompt 2) |
| DISC-15 | Who owns :80 and :443 — host nginx, `docker-proxy` → container, something else, nothing, or two instances configured for the same port. | `ss -ltnp` → pid → host nginx, or `docker-proxy` → published port → container. Configured listens from each instance's config. | Shows the owner of each port; flags instances whose config wants a port another instance owns (only one can bind it). Picks or asks for the front door. | unit: discover TestParseSSAndOwners, TestPortConflictAndNobody, TestDockerDiscovery (docker-proxy → container, front door) | done (prompt 3) — owners, conflicts and the front door are detected; config `frontDoor` picks another default for route add |
| DISC-16 | Kubernetes ingress-nginx present. | Processes/containers named `nginx-ingress-controller`, a kubelet on the host. | Reported as out of scope; never touched. | unit: discover TestHostDiscovery (kubelet process) | done (prompt 2) — kubelet and `nginx-ingress-controller` processes; ingress containers under containerd are not listed |
| DISC-17 | nginx running inside an LXC/VM or on another host. | Not visible from here at all. | Out of scope; doctor and the "no nginx" screen say that only this machine is scanned. | unit: discover TestHostDiscovery (master in a namespace Docker does not own), TestNoNginxAnywhere | done (prompt 2) |
| DISC-18 | systemd drop-in changes ExecStart (`-c` elsewhere, `-g` directives). | `systemctl show -p ExecStart,DropInPaths`. | The drop-in's `-c` and `-g` win over the defaults; shown in the instance details. | unit: discover TestHostDiscovery (drop-in ExecStart with -c, -g), TestCmdArgsAndExecStart | done (prompt 2) |

## CONF — configuration reading

| ID | Situation | How NgiTool detects it | What NgiTool does | Test | Status |
|---|---|---|---|---|---|
| CONF-01 | `include` with globs, sites-available/sites-enabled symlinks, conf.d. | Parser follows `include` relative to the prefix; globs expanded in nginx's order; symlinks resolved. | Tree shows each server under the file that really defines it; the symlink (enabled) vs target (available) distinction is kept. | unit: nginxconf TestDebianLayoutWithSymlinks, TestIncludeGlobOrder, TestSplitDump | done (prompt 2) |
| CONF-02 | `nginx -T` unavailable (stopped container, missing binary). | `-T` fails or cannot run. | Resolves includes from the files themselves (host paths, or the container's bind mounts mapped back to the host). | unit: discover TestDockerDiscovery (stopped static-site through its mount), TestHostDiscovery (host files when -T fails); integration TestIntegrationScan (stopped) | done (prompt 2) |
| CONF-03 | The config is already invalid before any change. | `nginx -t` fails before NgiTool has written anything. | Instance is read-only until fixed; the error (file:line) is shown; nothing is written on top of a broken config. | unit: discover TestInvalidRunningConfig, nginxconf TestInvalidConfigIsParsedWherePossible | done (prompt 2) |
| CONF-04 | Parser robustness: quotes, escapes, regex `server_name` and `location`, comments, `if` blocks, `*_by_lua_block` bodies. | Tokenizer with nginx's quoting rules; lua block bodies captured as opaque text. | Everything round-trips; unknown directives are kept verbatim, never dropped. | unit: nginxconf TestLexerEdgeCases, TestOpaqueLuaBlocks, TestRoundTrip (every fixture and the recorded dump) | done (prompt 2) |
| CONF-05 | Variables and `map` in `proxy_pass`. | `proxy_pass` argument contains `$`. | Shown as dynamic (with the map when it is simple); never "resolved" to one upstream. | unit: nginxconf TestSummaryOfEdgeDump (`set`), TestUpstreamEveryParameter (`map`) | done (prompt 2) |
| CONF-06 | Config baked into the image, no bind mount. | No mount covers the config path in `docker inspect`. | Read-only; offers an opt-in "externalize": copy the config to a host dir and add a compose override that mounts it. | unit: discover TestDockerDiscovery (App1, baked), TestCapabilityReasons | done (prompt 2) — detected, read-only with the reason; the opt-in "externalize" is prompt 3/4 |
| CONF-07 | Single-file bind mount vs directory mount; `:ro` mounts. | Mount type and `RW` flag. | Single-file mounts are edited in place (rename would break the inode the container sees); `:ro` mounts are read-only with an explanation. | unit: discover TestDockerDiscovery (single-file), TestCapabilityReasons (:ro) | done (prompt 3) — the adopt include line is written in place on a single-file mount; `:ro` mounts are written from the host |
| CONF-08 | Official image templates (`/etc/nginx/templates/*.template`, envsubst at start). | Template dir mounted; rendered file in conf.d. | Edits go to the template, not the rendered file; `${VAR}` placeholders are preserved. | unit: discover TestDockerDiscovery (templates mount) | done (prompt 2) — detected and noted on write; editing templates is prompt 3 |
| CONF-09 | Hand-written files beside managed ones. | Managed files carry the `# Managed by NgiTool` header (the Node CLI used the same idea). | Hand-written files are never modified or deleted; conflicts with them are reported. | unit: nginxconf TestManagedHeader | done (prompt 3) — the writer only rewrites or deletes files that start with the NgiTool marker; a hand-written file at a target path is a hard error |
| CONF-10 | CRLF line endings, UTF-8 BOM, non-UTF-8 files. | Byte inspection on read. | CRLF and BOM are tolerated and preserved on write; non-UTF-8 files are read-only with a message. | unit: nginxconf TestLexerEdgeCases, TestParseFileInfo; discover TestCapabilityReasons (non-UTF-8) | done (prompt 3) — tolerated on read, non-UTF-8 is read-only; the one include line keeps a CRLF file CRLF |
| CONF-11 | `nginx -T` output contains secrets (API keys in headers, basic-auth paths). | Always. | `-T` output is parsed in memory and never logged or cached whole. | unit: discover TestDockerDiscovery (report holds no dump); review: dumps are only parsed, or printed by `inspect --raw` | done (prompt 2) |
| CONF-12 | `stream {}` blocks (TCP/UDP proxying). | Parser sees a top-level `stream` context. | Shown read-only as out of scope (see RP-14). | unit: nginxconf TestStreamIsReported | done (prompt 2) |
